Task 0. JavaScript Refresher

My JavaScript practice before React. All results come from script.js.

1. Variables and Data Types

A student: name, age, isActive, courses, address, plus null and undefined.

let can get a new value later. const cannot. But if a const holds an object, I can still change what is inside it. Only the box itself is locked.

typeof null gives "object". This is an old mistake in JavaScript. They keep it so old sites still work.

Primitive types: string, number, boolean, null, undefined, symbol, bigint. Objects, arrays and functions are not primitives.

2. Arrays

I use [3, 7, 2, 10, 5] with map, filter, find, reduce and includes.

All these methods give me a new value. They never change the old array. That is why my array is still [3, 7, 2, 10, 5] at the end.

I think this is important for React: we do not change data, we make new data.

3. Arrays of Objects

Four students: Anna 85, John 62, Sara 91, Mike 55.

filter makes a new array, but the objects inside are the same objects. So if I write student.passed = true, I also change the old data.

To be safe I make new objects: { ...student, passed: true }.

4. Objects

A user with address: { city, street } inside.

I can take a value from deep inside: const { address: { city } } = user.

I can also give it a new name with :. const { name: userName } = user.

5. Values and References

I start with { name: "Alice", score: 10 } and copy it in different ways.

copy = original does not copy the object. It only copies the address of the object. Both names point to the same box, so both change together.

Spread { ...original } makes a real copy, but only of the top level. Things inside (like address) are still shared. This is called a shallow copy.

To fix it, I copy the inside part too: { ...user, address: { ...user.address } }. Or I use structuredClone(user) for a deep copy.

6. Functions

isEven, getFullName, calculatePrice, calculateDiscount, getMax.

I wrote isEven two times: as a normal function and as an arrow function. Both give the same answer.

The difference: a normal function works even before its line in the file (hoisting) and has its own this. An arrow function does not.

7. Functions as Values

calculate(5, 3, add) gives 8, calculate(5, 3, multiply) gives 15.

Yes, I can put a function in a variable. In JavaScript a function is just a value.

Yes, I can send a function to another function. map and filter work like this.

add is the function. add() runs it and gives the answer. In React we write onClick={handleClick} without () for the same reason.

8. Scope

The same name message in three places: global, function, block.

Global scope: I can use the variable in the whole file.

Function scope: only inside the function.

Block scope: only inside { }, for example in an if.

var does not stay in the block, so I can still use it outside. let and const stay inside, and const cannot get a new value. Today we use let and const.

When two variables have the same name, the closest one wins. That is why I see "block" and not "global".

9. Closure

createCounter() counts 1, 2, 3. createAdder(5) makes addFive.

A function remembers the place where it was made. createCounter is already finished, but its count is still alive, because the small function inside still uses it.

Every call of createCounter() makes a new place, so the second counter starts from 1 again.

For me this looks like useState in React.

10. Destructuring, Spread and Rest

numbers = [10, 20, 30, 40], user = { id: 1, name: "Anna", age: 21 } and sum(...numbers).

Spread and rest look the same (...) but do opposite things.

Spread opens something I already have: [...numbers, 50].

Rest collects many things into one: function sum(...numbers).

Easy rule: in a function's parameters it is rest. Everywhere else it is spread.

11. Optional Chaining and Default Values

Some users have an address, some do not. I test ?., ?? and ||.

user.address.city gives an error when there is no address. user.address?.city gives undefined and does not break the page.

|| changes every falsy value, so 0, "" and false also become the default text. This can be a bug: a price of 0 looks like "no price".

?? works only with null and undefined, so 0 and "" stay. For default values ?? is usually better.

Final Task

Five students with a grades array. I build { id, name, average, passed } for each one.

Every function here only takes data and gives back new data. Nothing changes the old array.

At the end I check this: I save the students as text before and after, and compare. The result is "yes", so my data is safe.
